# Agent local API v1

Status: T01 contract for both agent modes, revised 1/11 for Land checkpoint coordination and reserved reward snapshots. Wire version 1, strict schemas below; private material is NEVER returned. Numeric errors are exactly [v1.md](v1.md). This API does not implement chain operations. The two-hash protocol manifest intentionally does not pin this independently versioned local document.

## Common encodings, authentication and bounds

JSON is strict UTF-8, one value, no duplicate/unknown properties, trailing data, NaN, fractional integers or coercion. Object member order/whitespace is irrelevant. u64 is a canonical decimal string in 0..18446744073709551615; keys/hashes are lowercase 64-hex, id is lowercase 32-hex, bytes are canonical unpadded base64url. Validate decoded byte lengths/UTF-8 lengths as well as schemas; JSON Schema string length alone counts characters and is insufficient. No null for absent optional fields. UUIDs are lowercase RFC4122 version-4 strings, random per logical mutation, not per retry. All mutations carry `Idempotency-Key: <UUID>`; binary profile uses the same header. Node channel uses its envelope id instead. Tokens are 32 random bytes, encoded base64url in `Authorization: Bearer <token>`; comparisons are constant-time.

Bind ONLY 127.0.0.1. Exact `Host: 127.0.0.1:<actual-port>` on every HTTP request/upgrade/static path; reject aliases, alternate IP spellings, DNS and forwarded-host overrides. Player browser mutations/upgrades require exact Origin `http://127.0.0.1:<actual-port>`; reject null, missing or foreign. Native absent-Origin API HTTP requires install token, never a browser capability; native bridge WS requires token plus handle. Check Fetch Metadata when supplied; reject cross-origin preflight, no wildcard CORS. Browser API GETs require capability and reject foreign/null Origin if supplied; GET never mutates. Static shell/assets are an explicit authentication exception: serve them on loopback without capability or install token, enforcing exact Host, traversal protection and CSP; they MUST contain no secrets. Node/admin reject EVERY Origin header, including null, require separate same-user tokens, have separate ports. Tokens remain owner-only files with POSIX 0600/directories0700 or Windows current-user ACL/inheritance disabled. No token in URL/log/UI bundle/browser storage.

Launcher creates one-use 256-bit bootstrap secret expiring after 60 monotonic seconds; browser receives fragment, removes it immediately, referrers disabled. POST `/v1/local/bootstrap` exchanges it for in-memory UI capability lasting at most 8 hours. Bootstrap is an explicit capability exception: authenticate with the one-use secret and exact Host/Origin, with no capability required beforehand. Capability is held in browser memory, Authorization for API/fetch-streamed events; bridge handles are separate unpredictable 32-byte tokens scoped to capability/session and exact Origin. No EventSource without authentication. Handle dies with session/capability. Renewal requires an explicit native launcher action authenticated by the per-install token, issuing a new one-use bootstrap and new in-memory capability; the old capability cannot mint or extend its successor. Prompt before expiry to reopen through the launcher. Expiry or replacement revokes the old capability, closes its streams/handles/game session, and requires fresh Enter/NK/proof/seat. A sleeping tab must rebootstrap and cannot reuse expired handles. Keep the 8 h maximum; T09/T10 test fake-clock expiry/replay and T13 counts real-browser renewal interruptions and fresh-entry attempts in soak evidence. CSP permits bundled scripts/styles and same-origin connects only, frame-ancestors none; nosniff, no external scripts/card HTML. Static paths reject traversal. Keys/signing/file access are not browser endpoints. Loopback does not protect against same-user malware/admin/extension/XSS.

Player request <=8192 bytes except binary profile <=9216; nonstreaming response <=524288 (directory <=64 entries); event record <=16384 with no total stream-length limit. Limit 120 requests/min/UI capability (native token uses equivalent bucket), including mutations, plus upstream section-13 budgets. Event subscriber queue max64 records, overflow disconnects BUSY; client re-reads current state, events are hints not durable authorization. Maximum32 outstanding local requests, reject excess BUSY. Node WS frame<=16384, outstanding32, queue64, no compression, overflow BUSY/disconnect. Local requests deadline<=30 s, stream/event connection may persist with each event bounded. Bridge uses 64 KiB HTTP request/512 KiB response, 16 KiB up/1 MiB down WS, 8 streams/2 HTTP/1 WS, 10 s reassembly deadline and v1 queue budgets. No configuration raises these wire maxima. Owner admin requests <=8192, list limit<=100. Hub preferences<=8; protected contacts/high-water<=10000, never silently evict; separate unselected discovery cache<=10000, evictable and unable to consume protected quota.

## Player API `/v1/local`

JSON requests/responses use application/json, except profile application/octet-stream and events application/x-ndjson. Errors are Error schema, no internal strings/stack traces. Responses containing secrets/invites/reservations use Cache-Control:no-store. Schemas are named in the registry below; HTTP request/response has no extra wrapper. Empty request means exactly `{}` where a body is allowed; bodyless GET/DELETE must not carry content (DELETE still needs mutation UUID). Query parameters reject duplicates/unknowns and use canonical decimal/hex. URI path fields have the same schema as their body equivalents.

### Land durable-state coordination and recovery

Only the Land agent/Node use this contract. Agent-owned restore-state.json stores restore epoch, publication high-water and any pending checkpoint outside land.db. Node stores the matching epoch checkpoint and card revision in its WAL/FULL transaction. All security/reward mutations and their durable UUID outcomes advance the epoch and card counter before success; publication persists the agent high-water before signing/sending. Serialize this coordination across admission/admin/policy and reward work; no further serving or mutation success acknowledgement while a checkpoint is pending, except the prepare/commit exchange needed to complete it.

Node sends `prepare_state` with StateCheckpoint `{previous_epoch,restore_epoch,card_revision}` before its transaction: previous_epoch must equal the reconciled epoch, restore_epoch must be previous_epoch+1 and card_revision strictly above the prior counter/high-water (overflow fails closed). Agent durably reserves this checkpoint and fsyncs before replying with that exact StateCheckpoint. Node then commits the mutation, UUID/outcome, epoch and card counter in one SQLite transaction, and sends `commit_state` with the identical checkpoint only after durable commit. Agent requires the matching pending checkpoint, fsyncs its committed epoch/high-water and clears pending before returning it; only then may Node acknowledge success or either process serve further work. Identical UUID/checkpoint retry is idempotent; changed or unmatched checkpoint fails closed. A failed Node transaction, channel loss or process crash during coordination keeps serving blocked until explicit reconciliation; neither side may discard a pending checkpoint or infer success from a card-counter bump. No prepare/commit from an unreconciled/restored channel may clear a recovery lock.

Startup `sync.restore_epoch` must equal the committed agent epoch and `sync.card.revision` must be at least the agent publication high-water before serving; sync is an assertion, never a request to overwrite the agent sidecar. A pending checkpoint, epoch mismatch or lower card counter returns STORAGE_UNAVAILABLE and keeps entries/publication/spending closed. Normal higher-revision publication follows reconciliation. C2 adds reward authorization/cap/reservation/reference files to the same coordinated durability boundary before rewards are enabled.

Back up the matched identity, restore-state.json, land.db and enabled reward files with mutations/spending quiesced and SQLite backup API/VACUUM INTO or clean shutdown/completed WAL checkpoint. Identity/sidecar/DB/reward files restore together; no DB-only restore. An older DB or older matched bundle blocks serving; restore/import must compare verified prior epoch/publication upper bounds held outside the bundle. Unknown freshness stays closed. CLI recovery requires explicit reconciliation of lost-window used/revoked codes, removed members, bans and reward/idempotency state (uncertain rights denied, unknown budget/outcomes reserved/spent), or new identity without importing unreconciled authority. A counter bump alone never unlocks; under the same identity advance epoch/card counter above verified bounds plus safe margin without u64 overflow. Even a new Land identity cannot reset an imported wallet budget. Record acknowledged data loss; it cannot satisfy the zero-lost-commits milestone. Binary rollback retains current DB/reward state and requires the tested schema/API compatibility tuple. Hub has no restore feature or epoch.

## Agent <-> game-Node local API

Node opens authenticated WS to land agent `/v1/node/channel`; bind127.0.0.1, exact Host, no Origin, separate32-byte token. One active reconciled Node channel; authenticated replacement closes prior sessions/generations. Strict JSON frame Request or Reply schema below, version1 in requests, UUID id, agent boot_id and monotonic deadline. Reply echoes id/boot_id; exactly result OR numeric error. Result schema is determined by original request kind; unknown ID/duplicate response is rejected. Fixed kinds only, never arbitrary signing bytes. Events also use Request with id/deadline and receive Empty acknowledgement; at most32 outstanding covers both directions.

### Clock and reconciliation

Agent boot_id is random16 bytes per process. Agent clock is nonnegative elapsed MONOTONIC milliseconds since startup, decimal u64 (never wall time). Deadlines in channel envelopes, seat_deadline and drain refer to this clock and boot; network timestamps remain Unix seconds. No cross-process comparison of Go/Node native clock origins is allowed.

Agent first sends Announce schema as unsolicited handshake (not a command): `{version:1,boot_id,kind:"announce",body:{tick}}`. Before entries Node sends `sync` with body `{node_boot:<random16>, ...committed policy/card/caps...}`. Initial sync is the sole request allowed deadline="0"; it is bounded by agent10 s channel-auth/reconcile timer. Node records local monotonic send time t0 and receive time t1; reply includes agent tick a sampled when responding. For future agent-clock deadline d, Node computes its conservative local deadline `t0 + (d-a)` milliseconds (reject d<=a or already expired). The agent sample occurred after t0, so this never grants extra time; transit/calibration uncertainty can only shorten allowance. To generate a Node request budget b<=30000, use agent deadline `a + b`; reject expired rather than extend for elapsed transit. Node recalibrates with sync; previously assigned local deadlines never increase. Neither clock may use wall time; clock failure/overflow or boot mismatch closes channel. Do not use unbounded drift correction. Same-host clocks must both include suspend or close all sessions on resume before serving requests. Implementation must verify this on Windows/Linux.

Every calibration uses a fresh sync UUID. A retry with the same UUID retains its ORIGINAL t0; a cached tick must never be paired with a new send time. Node sync reconciles durable metadata and caps; agent validates policy/card revisions against remembered state, supplies fresh Noise key in new card, never signs a reused revision after agent restart. Agent gates entries until synchronization AND higher committed card publication complete. Node boot change fences all old generations/capabilities/reservations/sessions. sync includes the DB restore_epoch checkpoint and is also allowed for calibration with unchanged metadata; it never changes durable policy, grants seats or clears a restore lock. Reconcile it with the agent sidecar using the Land durable-state contract above. All ordinary deadlines must satisfy agent_now < deadline <= agent_now+30000, and drain.body.deadline cannot exceed envelope.deadline.

## Reserved for C2/C3/C4/C5 — non-executable stubs

These names are NOT accepted by the v1 executable channel union or Player route table; return NOT_FOUND for reserved endpoints and MALFORMED for unknown channel kinds. The reserved RewardTransfer schema below fixes the required snapshot-carrying fields only; it does not enable a channel command. No chain-specific address format, amount/fee units, transaction layout, mining command schema or chain error taxonomy is invented here. C2/C3/C4/C5 must version their bounded schemas, mutation IDs and replay behavior under the same localhost protections.

- C2 wallet balance and fixed-type send: explicit user approval of destination, amount and fees; no generic RPC proxy/arbitrary signing/key-export endpoint. Wallet branch comes from v1 paths; traffic direct to chain.
- C3 mining start/stop/status: off by default; consent screen AND authenticated current-session in-mine state, fail closed on missing/stale state. Stop on leave/loss/revoked consent/Stop; CPU cap, visible indicator, available stop button; decentralized pool traffic never in Hub tunnel. C0 gate applies.
- C4 Node `reward_transfer {player_key,wallet_snapshot,amount,reference_id}`: only Node spending request, matching the reserved RewardTransfer schema. Before Node commits acceptance of reward/fulfillment terms, the agent durably binds reference_id, player_key, the wallet snapshot from the verified GREETING and authorized amount/terms in its own authorization store, then returns that authorization outcome. Same reference/identical terms is idempotent; unknown reference or conflicting snapshot/player/amount/terms fails. Transfer must match the stored authorization exactly, never the current session wallet. An absent/empty or chain-invalid wallet is not payable. A Node-supplied snapshot cannot authorize itself or override the binding. Payout survives disconnect, W1-to-W2 wallet changes and agent/Node restart: pay the original W1 once. C5 persists fulfillment ID/terms and snapshot in Node state; both stores retain snapshot until finality/fulfillment expiry, then delete it while preserving the reference outcome needed to prevent replay.
- Both owner-set per-transaction and per-UTC-day caps count total wallet debit: amount plus all network/priority fees, with overflow-checked arithmetic. Estimate and atomically reserve amount plus a fee ceiling in agent-owned cap/day state and fsync BEFORE signing/sending; reject if either cap cannot cover it. Fee bumps/replacements reserve additional debit under the same reference and applicable UTC-day budget before signing, verify outputs/change and enforce the fee ceiling; release excess only after a definitive outcome. Day key is UTC date, retaining the latest day on clock rollback. Corrupt/unreadable state or unknown pending outcome fails closed until CLI resolution; restart/rollover never re-grants spent cap. Restore/import locks spending until chain/pending outcomes and daily total debit reconcile; an existing seed import is never a new zero-budget wallet, even under a new Land identity. Include caps, reservations, authorizations and reference/transaction outcomes in the Land recovery bundle above. No mint/credit path, gold ledger in land.db, Node wallet keys or RPC spend. C4/C5 define chain-unreachable/pending/reorg handling and version their authorization/terms/result schemas before execution; test fees greater than rewards, priority fees, replacements, forged snapshots and offline/restarted W1 payouts.

## Strict JSON Schema registry (draft 2020-12)

Each named HTTP body/result validates against `#/$defs/<Name>`. Node command bodies/results additionally validate according to the direction/kind table; Request restricts each kind/body via oneOf. Reply.result is validated against the matching pending request's result definition (no unknown pending ID accepted). Encoded byte lengths, u64 range, UTF-8 byte limits, deadlines, field equality and revision/authorization/state conditions above are mandatory semantic checks, not waived by schema success. RewardTransfer is a reserved, non-executable body contract; it is deliberately absent from Request and Reply. C4/C5 must version activation and result/authorization schemas before use.

Specification choices where PLAN gives requirements but not syntax: `Idempotency-Key` and the typed routes/results above, UUIDv4 spelling, boot-scoped millisecond clock calibration with original-send-time retention, binary unsigned profile upload, `sync`/`announce` reconciliation schemas, and bounded event enums. The Player 32-outstanding/64-event-queue defaults reuse the Node channel bounds; pending invite refs use a 256-entry cap, Player volatile outcomes 20000, and durable outcome storage a configurable 20000-entry default. These are conservative local limits selected at T01, not additional PLAN claims. Durable UUID records cannot be discarded to re-execute an old mutation. Bootstrap uses one-use-secret replay rejection instead of replaying a capability. RewardTransfer reserves the snapshot-carrying fields (reference_id uses UUID and amount uses U64); chain-specific semantics, authorization terms and activation remain C4/C5 work. StateCheckpoint and sync.restore_epoch specify T01 Land-only durability coordination; they add no wire message kind.
