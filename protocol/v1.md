# Linked Realms Connect protocol v1

Status: T01/T02 acceptance path owner-decided 1/11 (PLAN T01/T02 revised); T01 locks two hashes with spec-level checks only. Phase-2 quest pagination is resolved by owner decision A (2026-10-31). Normative words MUST, MUST NOT and SHOULD have their usual requirement meanings. All sizes are bytes; KiB = 1024 and MiB = 1048576. This document, including its decisions appendix, defines v1 independently of the implementation plan. No admission authority belongs to a Hub. No chain RPC, transaction, balance or mining traffic traverses a Hub. The optional encrypted GREETING wallet address is the sole wire address exception.

## Canonical encoding

Concatenation is written `||`. Integers u8/u16/u32/u64 are unsigned, fixed width, big-endian; u64 is bigint in TS. `key` and `hash` are exactly 32 bytes; `id` is exactly 16 bytes; Ed25519 signature is exactly 64 bytes. No padding or alignment. A field with no explicit type uses these aliases: player/land/poster/taker/noise_key = key; sid/route/connection/boot/quest_id/seat/fulfillment_id = id; *_hash/challenge = hash; revision/*_revision/counter/generation/quantity/deadline/observed_at/issued_at/expires_at/hub_time = u64; reason = u16. Times on the network are Unix seconds. Lengths count octets, not characters.

`blob` = u32 length || exact bytes. `text` is blob framing over strict UTF-8, without normalization; reject invalid sequences, surrogates and overlong encodings. `list<T>` = u16 count || repeated T. `optional<T>` = u8 0 with no following value, or u8 1 followed by exactly T. Boolean fields (online, final, binary, allow_guest) accept only 0/1; allow_guest MUST be 0 in v1. No implicit string terminators. Empty text/blob/list is permitted unless a minimum is stated. Optional present-empty is distinct from absent. Nested structures are inline, unless explicitly called blob. Decode under the outer size cap, check each count/length against both remaining input and its maximum before allocation, reject arithmetic overflow, truncation and trailing bytes at every boundary. Unknown kind/op is MALFORMED; unknown version is UNSUPPORTED_VERSION before body decoding.

Diagnostic JSON is never signed: u64 decimal strings without leading zeros (except "0"), keys/hashes lowercase hex, binary values unpadded canonical base64url. Local JSON details are in [agent-local-api.md](agent-local-api.md).

`endpoint` = origin:text<=192 || hub_key:key. Origins use lowercase ASCII `https://host[:port]`, DNS A-labels or canonical IP literals (IPv6 brackets), no userinfo/path/query/fragment, no trailing dot or default :443; nondefault port is decimal 1..65535 without leading zeros. Lists of endpoints are lexicographically sorted by UTF-8 origin, then raw hub_key, with no repeated origin or key. Reject noncanonical spelling rather than rewriting signed data. Approve origins locally, reject private/loopback/link-local DNS results except explicit operator dev allowlist, recheck at connect, reject redirects. Hubs never fetch advertised URLs.

DNS labels contain only lowercase a-z, 0-9 and internal hyphens, 1..63 bytes each, separated by single dots. IPv4 uses four decimal octets 0..255 without leading zeros. IPv6 uses lowercase hexadecimal groups without leading zeros, compresses the longest run of at least two zero groups (leftmost on ties), no zone identifier, no dotted-IPv4 suffix. International names must already be ASCII A-labels; decoding does not transform them. Unapproved/unresolvable endpoints are rejected before connection, not normalized into different signed bytes.

## Signed envelopes

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 4 | magic = ASCII LRC1 |
| 4 | 2 | version = 1 |
| 6 | 2 | kind |
| 8 | 32 | sender Ed25519 public key |
| 40 | 32 | recipient Ed25519 public key |
| 72 | 16 | context |
| 88 | 32 | nonce |
| 120 | 8 | issued_at |
| 128 | 8 | expires_at |
| 136 | 4 | body_length |
| 140 | body_length | body |
| 140 + body_length | 64 | signature |

Header = 140 bytes, overhead = 204. Sign pure Ed25519 over `ASCII("linked-realms/connect/control/v1\0") || header || body`; `\0` denotes exactly one zero byte, not backslash plus zero. Hashes naming an envelope are SHA-256 of its complete bytes INCLUDING signature, excluding WS discriminator or blob prefix. Verify canonical Ed25519 encodings, S < subgroup order, on-curve prime-subgroup non-identity public key and R, and the signature equation (no ZIP215 acceptance). Go and TS verification must agree; TS uses `zip215:false` plus any subgroup checks needed for these requirements.

Sender is the expected authenticated actor, not just any verifying key. Recipient is the exact peer; zero is allowed only for published CARD/QUEST_CARD and initial LINK_CHALLENGE. Context is current Hub boot for HTTP controls, connection ID for tunnel controls, exact Noise sid for encrypted controls, zero for objects/bootstrap. INFO_REQUEST is bootstrap with zero context and the configured Hub recipient. INFO reply has current Hub boot context. LINK_CHALLENGE has zero context/recipient; LINK_AUTH and LINK_READY use the challenged connection. CARD and QUEST_CARD use zero context. Local DOOR_SET uses Land sender/recipient and current Land boot context. Nonces are fresh random 32 bytes for each control; stored-object reading does not execute its nonce. Identical publication is idempotent; wrappers always have fresh nonces.

Every Hub-authored body begins with `request_hash:hash || hub_time:u64 || hub_boot:id` (56 bytes), INCLUDING LINK_CHALLENGE, ROUTE_OFFER, DRAIN and ERROR. A direct reply names the exact signed request hash; unsolicited notifications have zero request_hash. Route offer is an unsolicited notification to Land (zero hash), ROUTE_READY is the direct reply to the Player's ROUTE_OPEN. Only Hub-authored instances have this prefix. Hub acknowledgements have no admission authority. Expected role, route ownership, recipient, context and protocol state MUST also pass.

## Signed profiles and invite links

`signed_profile = player_key:key || revision:u64 || display_name:text<=32 || avatar_kind:u8 || avatar:blob || signature:64`. Sign `ASCII("linked-realms/connect/profile/v1\0") || preceding fields`. It is inline in GREETING, not blob-wrapped. Entire profile <=9 KiB. Kind 0 avatar contains an allowlisted preset ID, 1..32 ASCII bytes from `[A-Za-z0-9_-]`; preset `default` MUST exist. Kind 1 contains mime:u8 (0 PNG, 1 JPEG, 2 WebP) then <=8192 image bytes, nonempty, dimensions 1..128 each and actual format matching mime. No SVG, HTML or remote URL. No profile expiry. Agent durably increments revision before signing; player_key equals GREETING sender. Land commits only for eligible keys; persist highest revision and original signed bytes. Lower is rejected, equal accepts only byte-identical bytes. Clients verify original signature/key/revision, retain high-water/conflict checks, escape text and use safe local img blobs/presets. Omission selects stored profile or key/default preset. Display name is not authority.

Invite blob: `version:u8=1 || land_key:key || hubs:list<endpoint>[1..8] || code:32 || expires_at:u64 || signature:64`. Sign `ASCII("linked-realms/connect/invite/v1\0") || preceding bytes`. URL is `linkedrealms://invite/<unpadded-canonical-base64url-blob>`, no query/fragment; decoded <=2048, URL <=3072. Verify signer/expiry before lookup, expiry has NO skew grace. No envelope/kind number, card or note. Opening displays fingerprint/expiry/approved Hubs and performs discovery only; redeem only on Enter. Code is random 256 bits, default expiry 7 days, maximum 30 days. Note <=256 UTF-8 bytes remains owner-local. Codes are single-use, not Hub state.

## Directory, revisions and admission

CARD sender=land_key; zero recipient/context. Full signed size <=4096; lifetime exactly 600 s; protocol_version=1; current_players<=max_players<=64. Refresh every 120 s and on restart/policy/endpoints change. Node commits strictly increasing revision before agent signs once and publishes identical bytes to all Hubs. Same revision requires identical signed bytes, lower revision fails; Hub tombstones until expiry+120 s. Card serving/new routes require now < expiry (no skew grace). Existing sessions may outlive cards. Current-boot cards remain available until expiry for NK prologues; never keep prior-boot Noise private keys.

Directory public pages sort lexicographically by raw Land key; cursor is exclusive last key, next is last returned key iff more results remain. Exact lookup has land present, cursor absent, limit in 1..64 as for listing, next absent, at most one result regardless of limit; unknown/expired gives NOT_FOUND. Invite-only cards never appear in listing/search. QUEST_QUERY has an optional exclusive cursor encoded as quest_id:16 || poster_key:32. QUEST_PAGE cards sort strictly lexicographically by raw (quest_id, poster_key); return only tuples greater than the cursor, with next equal to the last returned tuple iff more results remain, otherwise absent. An absent cursor starts at the first tuple. Different posters with the same quest_id coexist at a Hub; quest identity always remains (poster_key, quest_id). Player queries every approved/configured Hub, verifies signatures/expiry and merges by Land key at the highest revision. Unselected discovery occupies a separate evictable cache of at most 10000 entries and cannot consume protected-contact quota. Only explicit contact selection/Enter or a user-approved trusted import promotes a new key, persisting revision/hash BEFORE use. Observations of already protected keys always persist higher revision/hash before use, including listing. Equal-revision disagreement is error. Never evict/roll back protected marks after restart/cache pressure/Hub failure; 10000 protected contacts/high-water marks maximum, reject new additions. Only explicit contact deletion with warning removes marks. Restore retains these marks; an older Player backup can lack newer observations.

Open means a live authenticated Land tunnel on at least one Hub, not card freshness/population. DIRECTORY_PAGE online is that Hub's live-tunnel observation at observed_at; observed_at=hub_time for the page snapshot. UI requires a fresh request-bound signed reply, not cache-only evidence; card must also be unexpired to serve an online entry. Closed/replaced/timed-out tunnels clear observation immediately. A silent blackhole can overstate online for up to 90 s. Hub restart has zero open tunnels. Hub cards, tunnels, routes, nonces, rate buckets and quests are RAM-only and disappear on restart; deployment config and its own identity/pins are provisioned inputs, with no Hub state backup or restore feature. Agents republish cards and reconnect. Rebuilt-Hub readiness (all ten milestone tunnels and current cards) must occur within 45 s of connectivity returning, separately from gameplay recovery within 45 s of failure injection. Readiness ends the Hub gauge exclusion; deadline overruns fail and all probe failures remain in the denominator. Changed Hub identity at the same origin requires explicit local fingerprint approval; never repin from TLS/origin alone. Lands then publish higher-revision endpoint cards; Players approve the pin or use another approved Hub. Confirm reachability by actual route/entry; OFFLINE/transport failure tries another Hub. STALE_CARD or NK failure permits ONE shared refetch-all-Hubs/retry with a fresh session; never downgrade or loop. A live tunnel with expired card remains connected but undiscoverable/not enterable. Multiple Hubs cannot eliminate withholding from an eclipsed client.

Admission sequence: authenticate hop, ROUTE_OPEN with exact current card hash, NK, GREETING, CHALLENGE, PROOF, durable Node decision, SEAT_GRANT or generic ENTRY_DENIED, reservation, WS join. Hub checks signatures/live tunnel/card/limits only. ROUTE_OFFER never reserves a seat. At offer receipt, before allocation/DH, reserve pending capacity inside the 80 aggregate Land sessions across all connections: at most 16 unauthenticated pending routes/Land and 8 per authenticated Hub identity across all its connections. Hold pending quota until valid PROOF or close. A fixed 10 s monotonic offer-to-verified-GREETING deadline covers NK and is never extended by partial traffic, heartbeat or reroute; timeout closes the route and releases all pending resources. Reroute is a new quota/rate-limited attempt. Apply on TCP and WSS alike; after verified GREETING the challenge deadline applies. Before acceptance, only entry SIGNED_CONTROL, PING/PONG and SESSION_CLOSE are allowed. Challenge is fresh random 32 bytes stored by (player,sid), bound to Land boot/policy and completed handshake hash via PROOF, atomically consumed before Node handoff. Ban wins over owner/public/invite membership. Node commits code consumption AND persistent membership transactionally before allow. Byte-identical PROOF replay is REPLAY; lost-reply recovery uses a fresh session/challenge/PROOF. Same used code/same key is idempotent only if membership remains and bans permit; other key fails; expiry/revoke of used code does not remove membership, removed membership is not restored by retry.

Challenge <=30 s monotonic. Seat has ONE <=30 s monotonic deadline through reservation and WS join, bound to (player,land,sid,boot,generation,policy_revision); SEAT_GRANT boot is inherited from authenticated CHALLENGE/session. No retry extends it. Only proven accepted entry replaces/fences old same-key Land generation; challenge alone never evicts. Policy changes cancel pending challenges/seats, increase revision, republish, eject ineligible sessions. Land shares challenges/seats/nonces across Hubs; caps 160 pending challenges/80 seats, 2 challenges/1 seat per key, 80 aggregate sessions including pending offers and 64 joined seats. Serialize decisions across I/O, recheck generation/policy afterwards, fail closed on unreconciled durable state. A Player agent closes its one current session/game WS/route before any new entry, even if new entry fails. Copied keys/another agent are outside that agent-local single-session guarantee.

## Noise and record framing

Only `Noise_NK_25519_ChaChaPoly_SHA256`, implemented by agent-only flynn/noise, no handwritten handshake. Initiator is Player, responder is Land with current card Noise static key. Prologue EXACTLY `ASCII("linked-realms/connect/noise/v1\0") || u16(1) || player:key || land:key || sid:id || SHA256(full_signed_card)`. No route, wallet, or additional field in prologue. NK handshake application payloads are empty; no sensitive data before completion. PROOF.handshake_hash is the completed Noise handshake hash. Reject invalid/all-zero DH. T02 pins dependency version/commit/hash and review evidence and supplies full NK transcript/AD negative vectors; T01 does not claim a Noise implementation or audit.

WS discriminator 0 prefixes exactly one envelope (record <=32768, envelope <=32767). Handshake/transport use the following header, where type itself is the discriminator (do NOT prefix it again):

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 1 | type=1 handshake or 2 transport |
| 1 | 2 | version=1 |
| 3 | 16 | route |
| 19 | 8 | sequence |
| 27 | 4 | length of all bytes after header |

31-byte header. Handshake sequence=0; payload `card_hash:32 || Noise_message:blob`, total payload <=4096 including hash/length; one NK message per record in each direction. Card hash must match route/prologue; handshake header is routing framing, not added as Noise application AD. Transport payload is ciphertext <=32737 including 16-byte tag; plaintext <=32721. EXACT 31 header bytes are AEAD associated data in Noise transport WriteMessage/ReadMessage; no domain prefix or reserialization. Header sequence starts at zero independently per direction and equals Noise counter. Hub checks version/length/route ownership and forwards opaque bytes unchanged. Wrong route/version, tag failure, repeated/skipped/reordered counter or exhaustion closes whole session. Fresh session BEFORE 2^20 records or 1 GiB ciphertext per direction; no bespoke rekey, resume or nonce reuse. Erasure in Go is best effort only.

Blob signature envelope is bounded by remaining plaintext; no fragmented signed controls. 8 streams/session, 2 simultaneous HTTP and 1 game WS. Bodies below are ordered; headers=list<(name:text<=64,value:text<=512)> with <=16 pairs, strictly sorted unique lowercase ASCII token names, no CR/LF in either, encoded headers total <=4096 including count and lengths. Methods <=8 uppercase ASCII letters; paths <=2048 UTF-8 bytes and bridge allowlist below. total/offset/message_id are u32; final/binary are bool u8.

## Time, replay, versions and liveness

Executable envelopes live <=60 s. LINK_CHALLENGE/LINK_AUTH/LINK_READY/GREETING/CHALLENGE/PROOF/SEAT_GRANT/ENTRY_DENIED live <=30 s; seat/challenge body deadline cannot exceed its envelope expiry. Require issued<=expires; reject issued>now+120 or expires<now-120 (equal boundaries pass generic envelope checks). Objects enforce their own effective expiry with no grace. Arithmetic must be overflow-safe. Monotonic challenge/seat/session deadlines dominate wall-clock tolerance; skew NEVER adds to a 30 s seat. At acceptance set nonce removal no earlier than max(expires+120, acceptance_wall+180) translated to monotonic duration; maximum future-issued 60 s control can need 300 s. Rollback never advances removal. Keep (sender,context,nonce); cap Hub 200000, Land 20000, reject new work when full, NEVER evict live entries. Record rejected authenticated mutations too. Check freshness/context before side effects. Stale boot/connection/session is rejected after restart even with a valid signature.

Every Hub reply includes hub_time. Agent estimates offset using request midpoint, capped +/-120 s, never sets OS clock; larger discrepancy = CLOCK_SKEW and another Hub. Use that Hub's bounded offset only for its envelope checks; cannot extend Land-local invite/challenge/seat/session deadlines. URL/subprotocol/envelope/frame/card/prologue versions must all agree. No suite negotiation/downgrade.

Heartbeat every 30 s; no authenticated HEARTBEAT/matching ACK for 90 s closes tunnel and clears observation. Unrelated traffic does not reset it. One tunnel/Land/Hub; complete replacement auth before atomically clearing incumbent routes and switching liveness. Land keeps 2..3 outbound Hubs normally (1..8 configurable), retry 1,2,4,8,16,30 s with uniform half-to-full jitter; reset after 60 s healthy, connect/auth deadline 10 s. Player encrypted PING every 10 s, no matching PONG for 30 s triggers switch even with healthy hop. Close old WS/session/route, fresh route/NK/proof/seat/reservation/Client/Room, no action replay/reconnection token. Alternate attempts 5 s each within lab recovery target 45 s; total outage uses capped jitter. Permanent Land denial is shown, not retried at each Hub. Unknown-outcome HTTP is not silently retried.

## Keys and files

Player and Land each generate ONE 32-byte root seed from OS CSPRNG. All 32-byte values, including all-zero test entropy, are valid SLIP-0010 inputs; all-zero must never be deliberately generated for production. Hub uses its random 32-byte Ed25519 seed directly, no derivation or wallet. A future 24-word recovery encoding represents the same entropy, NOT a BIP39 stretched seed. No passphrase or PBKDF is applied. C1 selects A or B; neither paths nor these vectors change with that choice. Paths apply identically to Player and Land; separate roles normally generate different roots.

| Branch | Algorithm | Fixed path | Hardened indices (hex) |
| --- | --- | --- | --- |
| Identity | SLIP-0010 Ed25519 | m/0'/0' | 80000000,80000000 |
| Wallet A | BIP32 secp256k1 | m/1'/0' | 80000001,80000000 |
| Wallet B | SLIP-0010 Ed25519 | m/1'/0' | 80000001,80000000 |

These are project-private paths, not BIP44 coin registrations or existing wallet address standards. Root is used directly as master HMAC data. SLIP-0010 uses HMAC-SHA512 key ASCII `ed25519 seed`; BIP32 uses ASCII `Bitcoin seed`. Split 64-byte result into left private bytes and right chain code. Hardened child HMAC data is `00 || parent_private:32 || index:u32` with parent chain code as HMAC key. Ed25519 child private bytes are the new left half, consumed as Ed25519 seed; public key is 32-byte RFC8032 encoding WITHOUT SLIP's diagnostic 00 prefix. BIP32 child scalar is (left + parent) mod secp256k1 order, serialized to EXACTLY 32 bytes including leading zeros; public key is 33-byte compressed SEC1. Invalid master/child scalar (master zero or >=order, child left>=order or sum=0) fails this fixed profile: do not silently increment an index, retry a different derivation, or change root on import. Identity still exists but unavailable wallet A must fail closed; initial creation can reject that root before use. No mnemonic-passphrase stretching, wallet keys in files, public derivation, or on-chain identity binding.

Derivation definitions and known answers are checked against [SLIP-0010](https://github.com/satoshilabs/slips/blob/master/slip-0010.md) and [BIP32](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki). The isolated generator compares Ed25519 HMAC and independently composed SHA512 ipad/opad paths; BIP32 is compared between pinned hdkeychain and separate fixed-width big-integer CKD. Published master/child known answers prevent circular agreement.

`identity.json` is strict UTF-8 JSON <=2048 bytes INCLUDING whitespace. Exactly these required fields, no duplicate/unknown fields, no trailing JSON; order/whitespace not significant:

## Decisions made while specifying

1. PLAN delegates paths to T01 without numbers. Freeze private m/0'/0' identity and m/1'/0' wallets, all hardened, no invented registered coin type; fail fixed-path BIP32 invalid derivation rather than moving paths. C1 still selects curve/foundation; address/transaction rules remain C2/C4.
2. PLAN now specifies wallet `optional<blob<=64>` (typo corrected 1/11), matching the existing optional u32-length blob encoding without changing bytes. signed_profile is inline by its declared type. Present-empty is allowed structurally; absence means no reward address. created_at in key JSON is canonical decimal u64, not an invented RFC3339 timestamp.
3. "Every Hub reply prefixes body" and unsolicited replies are resolved by prefixing ALL Hub-authored envelopes, even challenge/offer/drain; zero hash for unsolicited. INFO bootstrap uses zero context, configured recipient, reply current Hub boot. Challenge zero recipient applies only to initial LINK_CHALLENGE; encrypted CHALLENGE names Player and sid. 4. PLAN leaves endpoint sorting, cursor exclusivity, heartbeat ACK revision and header size accounting implicit. Freeze the rules above; exact lookup accepts limit in 1..64 with no cursor and returns at most one entry; sorted endpoints reject repeated origin OR key.
5. PLAN gives a deadline field but no cross-process monotonic representation. Local API defines a boot-scoped monotonic clock calibration with conservative deadline translation; network deadlines remain Unix seconds and never extend local budgets. JSON binary profile expansion would exceed 8 KiB/9 KiB, so PUT /profile uses bounded binary unsigned profile fields. Channel profile expansion still fits 16 KiB.
